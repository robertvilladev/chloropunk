# M4a — Run end Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A real end of run: a summary screen for victory and defeat (wave reached, kills, damage dealt, build) with "one more run", plus a best-wave record. Replaces the "RUN COMPLETE" stopgap.

**Architecture:** A pure `summarise(run): RunSummary` in `src/core/summary.ts` reads `RunState` and its run log (`src/core/runlog.ts` already records kills, damage and the build per wave). A new `SummaryScene` renders it with the widget kit (`panel`, `statTile`, `button`). `GameOverScene` is replaced by `SummaryScene` for both outcomes. Best wave lives in `src/core/settings.ts`-style storage (`vv.best`, try/catch like `settings`).

**Tech Stack:** Phaser 3.90, TypeScript strict, Vitest.

**Spec:** MVP spec §2 (complete run → summary → restart), §7 (Run summary screen), §2 non-goals (high score only). Mockups: run summary is in the screens artifact https://claude.ai/artifact/273SegSV2CBPS1HX96Yr17 (copy: `docs/superpowers/specs/mockups/Summary.dc.html`). Independent of the arena PRs.

## Owner-accepted resolutions (2026-10-24, from the session's readiness note)

1. The new pure function is `summariseRun` (`runlog.ts` already exports `summarise`). Read the plan's `summarise` as `summariseRun`.
2. **The mockup wins over the plan on content:** tiles WAVE n/10, SMASHED, DAMAGE, LEVEL (no scrap tile); title VICTORY (lime) / FLATLINED (danger); plus a small `BEST WAVE n · NEW BEST` line above the buttons.
3. Defeat subtitle is generic ("Taken down on wave 7. The boss waits on wave 10."); no killer tracking.
4. The best wave is updated when the run log is saved (death or last wave cleared), not when the summary shows, so leaving via MAIN MENU on the wave-cleared screen still counts.
5. Quits (pause → quit, wave-cleared MAIN MENU before wave 10) don't count towards the best wave; tested.
6. Build shown as weapon/item chips with no labels; overflow ends in a `+N` chip (no truncate helper).
7. Check in the browser that the summary sees the finished death record (saved one microtask after death).

## Review Focus

1. Long builds: 6 weapons + many items fit the summary (truncate with `…`, `core/labels.ts`).
2. localStorage blocked or full: best wave silently not saved, screen still renders.
3. Quit from the pause menu: no summary (goes to menu), no best-wave update? Decide: quits don't count; test it.
4. Restart from summary resets every per-run field (scenes are reused; `newRun()`).
5. Defeat on wave 1 with zero kills renders without NaN (damage share, averages).
